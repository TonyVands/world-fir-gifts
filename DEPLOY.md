# Деплой World Fir Gifts на Amvera и новогодняя ночь

## 1. Как устроен контейнер

Один Docker-образ: собранный фронтенд + FastAPI + встроенный PostgreSQL.
Данные Postgres, ключ шифрования (если не задан секретом) и бэкапы лежат в `/data`.
Amvera монтирует туда постоянное хранилище (`run.persistenceMount: /data` в `amvera.yml`).

> ⚠️ **Строго 1 реплика и 1 воркер.** Встроенный Postgres пишет в общий `/data`:
> если запустить две реплики, два Postgres начнут писать в один каталог и база
> сломается. Кеш витрины, rate limit и WebSocket-рассылка тоже живут в памяти
> одного процесса. Для масштабирования сначала переезжаем на managed PostgreSQL (раздел 4).

## 1.1. Как выкатываются обновления

Проект Amvera привязан к GitHub-репозиторию `TonyVands/world-fir-gifts`, ветка `main`
(classic-токен с правом `repo`, без срока действия). Каждый push в `main` запускает сборку.
Проверить выкаченную версию: `GET /api/health` → поле `version`.
После деплоя обновляйте страницу с Ctrl+Shift+R, чтобы браузер не взял старый бандл из кеша.

## 2. Переменные окружения (Amvera → проект → «Переменные»)

Секреты создавайте через «Создать секрет»: их значение потом не видно в интерфейсе.
Переменные применяются после **перезапуска** контейнера; на этапе сборки их нет.

| Имя | Тип | Значение | Зачем |
|---|---|---|---|
| `APP_ENV` | переменная | `production` | Выключает `/api/docs` и не даёт стартовать с публичным dev-ключом шифрования |
| `CONTACT_ENCRYPTION_SECRET` | **секрет** | случайная строка ≥32 символов | Ключ шифрования контактов. **Сохраните копию вне Amvera:** если ключ потерян, все контакты станут нечитаемыми |
| `CONTACT_ENCRYPTION_SALT` | секрет | случайная строка | Соль к ключу (менять нельзя после запуска) |
| `ADMIN_TOKEN` | **секрет** | случайная строка ≥32 символов | Админ-ручки: ручное формирование Кольца и скрытие шаров |
| `NEW_YEAR_UNLOCK_AT` | переменная | например `2026-12-31T21:00:00+00:00` | Момент распаковки (по умолчанию `23:59:59 UTC` = 02:59 МСК, см. раздел 5) |
| `RING_MATCH_AT` | переменная | пусто или ISO-время / `off` | Автоформирование Кольца. По умолчанию за 15 минут до распаковки |
| `SEED_ON_START` | переменная | `0` в проде | Демо-шары нужны только для витрины на старте. В Кольцо они не попадают |
| `MAX_GIFTS_PER_USER` | переменная | `3` | Лимит шаров на одного мастера |
| `DAILY_CANDLES` | переменная | `3` | Свечей в сутки на гостя (одна на шар); пополняются в полночь по Москве |
| `GIFT_EDIT_COOLDOWN_DAYS` | переменная | `5` | Как часто мастер может переделать свой шар (дней; 0 — без ограничения) |
| `PUBLIC_URL` | переменная | — | Адрес сайта для ссылок в превью и Telegram, напр. `https://world-fir-timyrabdrakhimov.waw0.amvera.tech` |
| `TELEGRAM_BOT_TOKEN` | секрет | — | Токен бота уведомлений от @BotFather. Без него уведомления просто выключены |
| `TELEGRAM_BOT_USERNAME` | переменная | — | Имя бота без @ (необязательно — бот узнаёт его сам) |
| `REPORT_QUARANTINE_THRESHOLD` | переменная | `5` | Сколько жалоб скрывает шар автоматически |

Если `CONTACT_ENCRYPTION_SECRET` не задан, ключ один раз генерируется в `/data/.contact_secret`.
Это работает, но ключ, заданный секретом, надёжнее: он переживёт даже потерю `/data`.

> **Смена ключа безопасна (с v16.1).** Если `CONTACT_ENCRYPTION_SECRET`/`SALT` поменяли, старые
> контакты расшифровываются прежними ключами (файл `/data/.contact_secret`, соль по умолчанию)
> и при старте перешифровываются новым — в логе «Перешифровано контактов новым ключом: N».
> Если в логе `CRITICAL … не расшифровываются ни одним известным ключом` — прежний ключ утерян:
> верните старое значение секрета/соли, иначе эти контакты партнёры не увидят.

Генерация значений: `python -c "import secrets; print(secrets.token_urlsafe(48))"`.

## 3. Порядок выката этой версии

1. Сделайте бэкап: скачайте `/data` или выполните `pg_dump` (раздел 6).
2. Задайте переменные из раздела 2 (как минимум `APP_ENV`, `ADMIN_TOKEN`, ключ шифрования).
3. Запушьте код. При старте автоматически выполнятся миграции (`app/migrations.py`):
   - добавится `users.is_demo`, демо-мастера будут помечены;
   - сессионные отпечатки заменятся их SHA-256 (старые браузеры продолжат узнаваться);
   - удалится старое демо-Кольцо, которое блокировало настоящее (409);
   - появятся уникальные индексы для `sequence_number` и рукопожатий.
4. Проверьте `GET /api/health` (версия `16.1.0`) и `GET /api/ring/status`.

## 4. Переезд на managed PostgreSQL Amvera (рекомендую до 31 декабря, если ждёте много людей)

1. Создайте кластер PostgreSQL в Amvera (раздел «Базы данных»).
2. Хост для подключения из другого проекта Amvera — внутреннее имя вида
   `amvera-<username>-cnpg-<project_name>-rw` (режим чтения и записи).
3. В приложении задайте секрет
   `WORLD_FIR_DATABASE_URL=postgresql://<user>:<password>@amvera-<username>-cnpg-<project>-rw:5432/<db>`.
   Именно `WORLD_FIR_DATABASE_URL`: платформенный `DATABASE_URL` entrypoint намеренно игнорирует.
4. Данные переносятся сами (v17.4.1): при первом старте с `WORLD_FIR_DATABASE_URL`
   entrypoint поднимает старую встроенную базу, снимает дамп и заливает его во
   внешнюю, если там ещё нет шаров. В логе: `[migrate] Готово: перенесено шаров — N`.
   Копия дампа — `/data/backups/premigrate_*.sql.gz`, подробности — `/data/migrate.log`.
   Повторно перенос не запускается (маркер `/data/.migrated_to_external`).
5. После переезда встроенный Postgres не запускается, бэкапы делает Amvera.
   Несколько реплик всё равно не включайте, пока rate limit и кеш живут в памяти (нужен Redis).

## 5. Новогодняя ночь: чек-лист

**Решите, когда «полночь».** Сейчас по умолчанию `2026-12-31T23:59:59Z`, это **02:59 по Москве**.
Варианты для `NEW_YEAR_UNLOCK_AT`:
- `2026-12-31T21:00:00+00:00` — полночь по Москве (основная аудитория);
- `2026-12-31T12:00:00+00:00` — полночь на Камчатке (первыми встречают Новый год — первыми и открывают).

**За неделю:**
- [ ] Переменные из раздела 2 заданы, контейнер перезапущен, в логе нет `CRITICAL`.
- [ ] Тариф с запасом по CPU/RAM на ночь (пик — первые 5–10 минут после распаковки).
- [ ] Проверен ручной бэкап и восстановление на тестовом проекте.
- [ ] Проверено, что `RING_MATCH_AT` стоит на нужное время: в логе при старте
      будет «Автоформирование Кольца Чудес запланировано на …».

**31 декабря:**
- [ ] **Не деплоить** после обеда: любой рестарт рвёт WebSocket-соединения и сбрасывает лимиты.
- [ ] За 15 минут до распаковки Кольцо формируется само. Если нужно раньше или вручную:
      `curl -X POST https://<домен>/api/ring/match -H "X-Admin-Token: $ADMIN_TOKEN"`.
- [ ] Кто повесит шар после формирования, но до распаковки, встраивается в Кольцо автоматически.
      После распаковки новые мастера в Кольцо этого года не попадают (видят пояснение).

**Если в ночь появился неприемлемый шар:**
```bash
curl -X POST "https://<домен>/api/gifts/<gift_id>/quarantine" -H "X-Admin-Token: $ADMIN_TOKEN"
# вернуть: ...?hidden=false
```
Пять жалоб от разных посетителей скрывают шар и без вас.

**Что уже сделано в коде против «новогоднего DDoS»:**
- витрина сериализуется один раз на изменение, отдаётся с ETag/304 и gzip;
- статические файлы `/assets/*` кешируются браузером навсегда (в имени файла хеш);
- запрос пар Кольца в первые 3 минуты разносится случайной задержкой 0–15 с
  и повторяется при 429/5xx; WebSocket переподключается с нарастающей задержкой;
- обратный отсчёт сверяется с часами сервера, поэтому сбитое время на телефоне не сдвигает распаковку;
- рассылка «полёта совы» идёт в фоне, параллельно и с таймаутом на каждого клиента.

## 6. Бэкапы

- Встроенный Postgres: `pg_dump` при каждом старте и далее каждые `BACKUP_INTERVAL_HOURS`
  (по умолчанию 6) в `/data/backups`, хранятся последние `BACKUP_KEEP` (14). Выключить: `BACKUP_ENABLED=0`.
- Скачать дамп можно из вкладки «Репозиторий» → `data/backups`.
- Восстановление: `gunzip -c world_fir_XXXX.sql.gz | psql -h 127.0.0.1 -U worldfir world_fir`.

## 7. Админ-ручки

Все с заголовком `X-Admin-Token`. Без заданного `ADMIN_TOKEN` они отвечают 503.

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/api/ring/match` | Сформировать Кольцо сейчас (409, если уже сформировано) |
| POST | `/api/gifts/{id}/quarantine?hidden=true\|false` | Скрыть или вернуть шар |


## Telegram-уведомления

1. В Telegram откройте @BotFather → `/newbot`, задайте имя (например «Всемирная ёлка») и username (например `world_fir_bot`).
2. Скопируйте токен и добавьте в Amvera секрет `TELEGRAM_BOT_TOKEN`, а также переменную `PUBLIC_URL`.
3. Перезапустите приложение. В логе появится `[Telegram] Бот @… на связи.`
4. Бот работает через getUpdates (long polling): вебхук не нужен, но реплика должна быть одна.

## Бот в мессенджере MAX (v17.4)

Те же уведомления, что и в Telegram, но в MAX. Включается переменными:

| Переменная | Что это |
|---|---|
| `MAX_BOT_TOKEN` | токен бота с платформы MAX для партнёров (business.max.ru) |
| `MAX_BOT_USERNAME` | имя бота без `@` (если не задано — берётся из `GET /me`) |
| `MAX_API_BASE` | адрес Bot API, по умолчанию `https://platform-api.max.ru`. Если MAX переведёт API на другой домен — поменяйте здесь, код трогать не нужно |

Бот работает long polling'ом (`GET /updates`), вебхук не нужен. Ссылка
привязки выглядит как `https://max.ru/<бот>?start=<код>`. Если заданы оба
токена, мастер выбирает мессенджер сам в меню «Уведомления».

## Ёлка как мини-приложение (Telegram и MAX)

Отдельной сборки не нужно — открывается тот же сайт.

* **Telegram:** в @BotFather → ваш бот → *Bot Settings → Menu Button* укажите
  адрес сайта. Можно также создать Mini App (`/newapp`) — тогда ссылка
  `https://t.me/<бот>/<app>?startapp=g_<id шара>` откроет сразу нужный шар.
  Сайт сам подгружает SDK Telegram, разворачивается на весь экран.
* **MAX:** в кабинете партнёра MAX добавьте мини-приложение с адресом сайта.

Встраивание разрешено только веб-версиям Telegram и MAX (`frame-ancestors` в CSP).

## Жители площади (v18.1, стиль «Пиксели»)

Жители — фигуры из кубиков (размер кубика 1/36 роста взрослого), «запечённые»
из реалистичных моделей Grab3D (лицензия CC0). Готовые данные — `frontend/public/models/vox/*.bin`
(≈ 0,5 МБ на всех): у людей 8 кадров шага + поза стоя, у зверей одна поза.
Дед Мороз (длинная шуба, посох) и Снегурочка-андроид (голубая шуба, кокошник, коса)
собираются при запекании. Пересборка: `tools/vox-bake` (см. комментарий в `bake_entry.js`).
Для распаковки текстур при запекании сайт не нужен; на сайте нужен только `blob:`/wasm в CSP (уже есть).

## Правовые документы и персональные данные (v18.2, 152-ФЗ)

Страницы: `/legal` (список), `/legal/privacy` — Политика, `/legal/consent` — согласие
на обработку, `/legal/publish` — согласие на распространение (имя и город на Ёлке),
`/legal/terms` — соглашение; `/.well-known/security.txt`.
При создании шара нужны три отдельные отметки (сервер без них отвечает 422);
версия документов и время согласия сохраняются у пользователя.
«Мои шары» → «Удалить мои данные» — `DELETE /api/users/me` (отзыв согласия).

Переменные окружения (пока не заданы, на страницах видны жёлтые пометки — **не публикуйте так**):

| Переменная | Пример |
|---|---|
| `OPERATOR_NAME` | Иванов Иван Иванович |
| `OPERATOR_STATUS` | физическое лицо / самозанятый / ИП |
| `OPERATOR_INN` | 123456789012 |
| `OPERATOR_EMAIL` | privacy@elkamira.ru |
| `OPERATOR_ADDRESS` | 101000, г. Москва, а/я 1 |
| `DATA_LOCATION` | Российская Федерация, г. Москва (Amvera, регион РФ) |
| `LEGAL_VERSION` | 2026-11-21 — меняйте при правке документов |
| `PURGE_CONTACTS_AFTER` | 2027-03-31 — после этой даты контакты стираются автоматически |

Важно: база с данными граждан РФ должна находиться в России (ч. 5 ст. 18 152-ФЗ),
а оператор до начала обработки подаёт уведомление в Роскомнадзор (pd.rkn.gov.ru).
Шрифты теперь отдаются с нашего сервера — запросов к Google нет.

Счётчик в меню: `GET /api/world/stats` — свечи и новые шары за сегодня (МСК), 7 дней и всё время, кэш 30 с.
